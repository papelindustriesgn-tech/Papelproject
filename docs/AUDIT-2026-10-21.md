# Audit et corrections du 21 octobre 2026

Branche : `claude/uny-audit-securite-xf13tt` (rien n'est déployé en production, rien n'est publié sur les stores).
Toutes les vérifications ci-dessous ont été faites **en local** (Supabase local dans Docker, données fictives),
sauf mention contraire.

## 1. Constats vérifiés et corrections

| Priorité | Constat de l'audit | Vérifié dans le code | Correction |
|---|---|---|---|
| P1 | Établissement en attente : accès aux dossiers | **Oui** : `is_university_member` acceptait `pending` ; `enrollments_read`, `university_enrollments`, l'historique et l'export CSV en dépendaient. N'importe qui pouvait créer un compte « établissement » rattaché à un établissement existant et lire ses inscriptions. | Données d'étudiants réservées aux établissements approuvés, par rôle (`university_can`), en base et côté serveur ; préparation de l'espace via `is_university_workspace_member`. |
| P1 | Tâches planifiées autorisées par User-Agent | **Oui** : sans `CRON_SECRET` (absent en production), `vercel-cron/…` suffisait. | `CRON_SECRET` obligatoire (≥ 16 caractères, comparaison à temps constant), jamais journalisé. |
| P1 | Coupons : contrôles et concurrence | **Oui** : quota flash dépassable en cas de demandes simultanées (reproduit 1 fois sur 3 avec l'ancienne fonction) ; à l'utilisation, offre, période, compte, statut et carte n'étaient pas revérifiés ; la vérification de carte acceptait une offre expirée. | Verrou par offre à la création, contrôles complets à l'utilisation (état « Réduction non applicable »), verrou de ligne conservé contre la double utilisation, offre valable exigée pour la vérification de carte. |
| P1 | Suppression du compte | Partiel : fichiers listés sur 1000 éléments sans pagination, erreurs ignorées. | Pagination, arrêt si un fichier ne peut pas être supprimé, journal sans secret ; page web `/supprimer-mon-compte`. |
| P1 | Caches après changement de compte | **Oui** : pages personnelles (dont portails établissement/partenaire) gardées hors ligne et servies après 3 s de réseau lent, sans lien avec le compte. | Portails, profil, notifications jamais mis en cache ; cache vidé à chaque changement de compte ; version du cache relevée. |
| P1 | Exploitation | Prévisualisations Vercel branchées sur la base de production ; SMTP et `UNY_MATCH_SECRET` absents en production. | Documenté (`docs/EXPLOITATION.md`) ; restauration testée sur base isolée (empreinte identique). |
| P2 | Parcours établissements | — | Accueil orienté actions (tuiles → listes filtrées), statuts cohérents (Soumise, À vérifier, **À compléter**, Validée, Refusée, Expirée), motif + responsable + date, rôles (administration, validation, consultation, annonces), équipe, historique, export journalisé. |
| P2 | Commerçants | — | « Scanner » en action principale, confirmation explicite, rôles responsable / caissier (base + interface), indicateurs séparés (vues, coupons générés, utilisés, achats confirmés), montants « déclarés », scan ≠ vente. |
| P3 | Étudiants | Jobs et logement retirés le 7/10 (données conservées). | Navigation Accueil · Avantages · Ma carte · Opportunités · Profil ; jobs, logement et marketplace rétablis dans Opportunités ; annonces de l'établissement sur l'accueil ; carte hors ligne datée ; brouillons de formulaires ; refus de caméra expliqué. |
| P3 | Site public | « Zéro fraude », délais absolus. | Entrées Étudiant / Établissement / Commerçant ; création du compte distincte de la validation ; promesses retirées ; politique de confidentialité réécrite ; démos exclues des statistiques admin. |
| P4 | Chaîne de publication | Deux projets Android avec le même identifiant ; TWA ciblant l'API 35 alors que Google exige l'API 36 depuis le 31/08/2026. | Google Play = `android/` (API 36, même clé) ; App Store = `mobile/ios` ; CI alignée ; carte hors ligne native dans l'app ; liens universels préparés ; modération marketplace (signalement, blocage, file admin, règles) ; dossier `docs/PUBLICATION-STORES.md`. |
